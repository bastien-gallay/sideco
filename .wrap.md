# wrap — sideco

## Canonical locations

- index: the `backlog` board (`sideco show --board backlog`): cards T…, lanes todo / doing / done
- roadmap: the `types-de-boards` story map (stories S…), ticked with `sideco done`
- lessons: CLAUDE.md (repo), CONTRIBUTING.md, docs/coding-standards.md
- requirements: docs/PRD.md, table « Exigences fonctionnelles » (F1…), one row per feature with its status
- user guide: docs/guide.fr.md
- release notes: CHANGELOG.md
- tracker: the backlog board itself; GitHub releases for versions

No ADR directory and no dated journal: decisions live in the PRD rows and in commit subjects.

## Verification commands

- blocking: bun run check (types, biome, markdownlint on every .md, unit tests)
- blocking: bun test tests/e2e (outside the sandbox: it starts Chrome and a server)

## Disposable zones

- the session scratchpad (outside the repo)
- .claude/worktrees/<name> once merged (another session may own one: check its last commit first)

## Commit conventions

- format: one sentence in English, stating what the change does for the reader, no prefix
- explicit paths in `git add`: a Claude Code hook in the user's own settings refuses -A, . and commit -a (the repo itself has no such guard)
- a pre-commit hook (.githooks, set by `bun install`) runs `biome check --staged`

## Notes

- Two sessions work here: sideco-ui (page, UX) and sideco-gq (CLI, domain, server, hooks). Freeze main when the other asks, until its « main libre ».
- Summary rows of the PRD (the ⚠️ column) and the guide's one-line descriptions keep superseded claims longest: grep them after any behaviour change.
- A line cap in biome.json may be lowered, never raised, even back to a value set earlier in the same branch: set it after the formatter has run.
